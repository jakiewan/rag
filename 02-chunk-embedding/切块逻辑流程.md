# Markdown 切块逻辑流程

> 对应作业第 1 题：完成 Markdown 文档的切块过程，整理思路，提交切块逻辑流程。

## 核心目标

把一份 Markdown 文档切成 **结构清晰、长度受控、可独立检索** 的小块（chunk），
保留章节语义（标题层级），控制单块字符数：表格作为不可拆原子（巨型表允许 > MAX_LEN）；普通 chunk 严格 `[MIN_LEN, MAX_LEN]` 区间，`MIN_LEN` 之下向同章节合并，`MAX_LEN` 之上二次切分。

## 五步流程

### 1️⃣ 输入 & 规范化

- 读 `sample_new.md`，把 `\r\n / \r` 统一换成 `\n`。
- 取文件名 `sample_new` 作为 `file_title`，用于无父标题时的兜底溯源。

### 2️⃣ 按标题一级切分（保留层级）

- 用正则 `^\s*(#{1,6})\s+(.+)` 识别 `# ~ ######` 标题。
- 维护 `hierarchy[1..6]` 记录各级最新标题足迹；遇到新标题时，**清空更深层级**，避免父级继承错乱。
- **代码围栏保护**：` ``` ` / `~~~` 内的 `#` 不算标题。
- 每个 section 携带：`title`、`body`、`parent_title`（向上找最近非空父级）、`file_title`、`level`。
- **preamble 合并**：第一个标题之前的图片/引言等前导内容，并入第一节作为题图/引言，**不产空标题块**。

### 3️⃣ 元素原子化（保护表格）

- 用正则 `<table.*?</table>` 把内容切成 `[文本块, 表格, 文本块, 表格, ...]` 序列。
- 表格作为**不可拆原子**整块入栈：`has_table=True`。
- 无论该 section 是否超长，**每个表格都被独立标记**（避免漏标）。

### 4️⃣ 长度控制（二次切分 + 短块合并）

- **超长章节二次切分**：用 `RecursiveCharacterTextSplitter(chunk_size=available)` 把超长文本切小；表格独立成块。
- **短块合并**（两道）：
  - 表格前的短文本 → 仅当该短文本的 title == 表格的 parent_title 时（即短文本是该 H2 节的引言），才并入表格；否则不合并（防跨节错位）。
  - 同一 `parent_title` 下、长度 < `MIN_LEN` 的相邻短块循环合并；**被合并章节的标题写进 body**（保留溯源）；合并后总长严格 ≤ MAX_LEN。
- **巨型表格**：自身超过 `MAX_LEN` 的表格保留为单块（不强行切碎，破坏语义）。

### 5️⃣ 组装 & 落盘

- 把 `title` + `body` 拼成最终 `content` 字段（`title\n\nbody`）。
- 每条 chunk 携带：`title / content / file_title / parent_title / part / has_table`。
- 备份到 `02-chunk-embedding/result/chunks.json`，供下一步向量化（`bge_m3_embedding_utils.py`）读取。

## 一图流

```
MD 文件
   │
   ▼  Step1 输入 & 规范化
   │
   ▼  Step2 按标题切分（hierarchy 追踪 + 代码围栏保护 + preamble 并入首节）
   │
   ▼  Step3 元素原子化（表格整块入栈）
   │
   ▼  Step4 长度控制（二次切分 + 短块合并 + 巨型表格单成块）
   │
   ▼  Step5 组装 content + 落盘 chunks.json
   │
   ▼
  28 个 chunk（18 个表格全部独立成块；4 个表格因巨型单成块超过 2000；其余 10 个 chunk 中 7 个为「关于 X 表的说明」类短说明，< 500 是合理的语义短节；其余 3 个非表格 chunk 严格 [500, 2000]）
```

## 关键参数

| 参数 | 值 | 含义 |
|---|---|---|
| `MAX_LEN` | 2000 | 单块最大字符数 |
| `MIN_LEN` | 500 | 触发合并的最小字符数 |
| `chunk_overlap` | 0 | 二次切分时不重叠（preamble 已天然衔接） |
| 表格策略 | 不可拆原子 | HTML 表格整体入栈，单成块或附前缀 |
